# Swipe Actions

> 리스트 행을 왼쪽으로 밀면 오른쪽에서 액션 버튼이 드러나는 모바일 전용 패턴. iOS Mail·메시지의 스와이프와 같은 동작으로, 행을 열어 상세로 들어가지 않고도 편집·삭제 같은 자주 쓰는 액션에 바로 닿게 한다.

리스트 행 자체를 다시 만들지 않는다 — **기존 행을 감싸는 컨테이너**다. 행의 시각·탭 동작은 그대로 두고 뒤에 액션 트레이를 붙인다. 그래서 `expense-row` 든 `todo-row` 든 감싸기만 하면 같은 제스처를 얻는다.

**액션은 고정 목록이 아니다.** 항목마다 할 수 있는 일이 달라서(문자함은 편집이 없고, 메모는 고정이 있다) 호출처가 1~3개를 조립한다. 스펙은 액션의 **모양과 배치**를 정의하고 **무엇을 넣을지는 정의하지 않는다**.

## Anatomy

```
     ← 왼쪽으로 드래그
┌──────────────────────────────┬────┬────┬────┬────┐
│ ⓐ row (기존 리스트 행 그대로)  │ 20 │ ⓒ  │ 12 │ ⓒ  │
│    탭 = 원래 동작(상세 열기)    │    │(삭제)│    │(수정)│
└──────────────────────────────┴────┴────┴────┴────┘
 └─ ⓑ track (배경 없음 — 행이 밀린 자리가 그대로 보인다) ┘
                                            마지막은 화면 끝에 딱 ┘
```

| ⓐ row | 감싸는 대상. 스펙은 행의 내부를 정의하지 않는다 — 높이·패딩·배경 전부 원래 행 것을 쓴다. 드래그 중 `transform: translateX(-N)` 만 받는다. |
| ⓑ track | 행 뒤에 드러나는 영역. **배경을 칠하지 않는다** — 색을 깔면 행 옆에 박스가 하나 더 생긴 것처럼 보인다. 색은 ⓒ 의 원형 배지만 갖는다. |
| ⓒ action | 원형 배지(아이콘) + 그 아래 라벨. 세로 가운데. 아래 Sizes·Kinds 표. |

## Kinds

`destructive` 는 **가장 안쪽(화면에서 가장 왼쪽)** 에 둔다 — 조금만 밀면 바깥쪽 액션부터 드러나므로,
파괴적인 것을 바깥에 두면 제일 먼저 손에 닿는다. 안쪽에 두면 끝까지 밀어야 닿는다.

호출처는 `[고정, 수정, 삭제]` 처럼 **의미 순서 그대로** 넘긴다 — 그리는 쪽이 뒤집는다.

색은 **원형 배지**가 갖는다(트레이 배경 아님). 라벨은 배지 밖이라 본문 색을 쓴다.

| Kind | 배지 채움 | 배지 안 아이콘 | 라벨 | 의미 | 사용처 |
|---|---|---|---|---|---|
| `neutral` | `--color-surface-input` | `--color-text-primary` | `--color-text-secondary` | 부수 동작 | 고정, 보관, 공유 |
| `primary` | `--color-info` | `--color-text-on-accent` | `--color-text-secondary` | 주 동작 | 수정 |
| `destructive` | `--color-error` | `--color-text-on-accent` | `--color-error` (다크 `--color-error-light`) | 되돌리기 어려움 | 삭제 |

`primary` 가 `--color-primary` 가 아니라 `--color-info` 인 것은 버튼 채움과 같은 기조다.

`destructive` 라벨만 다크에서 밝은 변형으로 갈린다 — `--color-error`(#DC2626)는 `surface-default-dark`(#242938)
대비 **3.0:1** 로 본문 기준(4.5:1)에 미달하고 `--color-error-light`(#F87171)는 5.24:1 이다. DESIGN 의
`alert-text-error-on-dark`(다크 표면 위 인라인 텍스트는 `-light` 변형) 규칙을 그대로 따른다. 배지 **안**
아이콘은 채움 위에 얹히므로 kind 와 무관하게 `--color-text-on-accent` 하나다 — 갈리지 않는다.

## Sizes

액션 버튼은 단일 사이즈다. 행 높이를 따라가므로 Height 는 컨테이너가 정한다.

| Size | Slot width | Badge | Height | Padding (Y · X) | Font (token) | Font (px) | Icon | Radius | Touch (AA · AAA) |
|---|---|---|---|---|---|---|---|---|---|
| `default` | 배지 + 앞 간격 (첫 액션 56, 이후 48) | 36 원형 | 행 높이 (min 56) | `0` · 앞 간격만 | `text-caption` | 12 / 600 / 1.3 | 18 | 원형(`--radius-full`) | ✅ · ✅ |

- **배지 36** — 행 높이 안에 원형과 라벨이 함께 들어가는 최대치. 40 은 라벨과 합쳐 넘친다(실측).
- **간격은 배지 앞에만** 둔다 — 첫 액션 앞 20, 액션끼리 12. 뒤에도 두면 마지막 배지와 화면 끝이
  벌어져 덜 열린 것처럼 보인다. **마지막 액션은 화면 끝에 딱 붙는다.**
- Height 는 행을 따라가되 **56 미만이면 56 으로 올린다** — WCAG 2.5.5(AAA, 44×44)를 밑돌지 않게.
  터치 대상은 배지(36)가 아니라 **슬롯 전체**(48~56 × 행 높이)다.
- **배지↔라벨 gap 2** — 배지 아래 라벨까지 한 덩어리로 읽히게 붙인다.
- **`text-caption` 은 font-size(12)만 토큰 그대로**, weight 600 · line-height 1.3 은 이 컴포넌트의 override 다
  (caption 토큰 원본은 400 / 1.5). 슬롯 폭이 48 로 좁아 기본 leading 이면 두 줄에서 넘친다.
- 사각 채움이 아니라 원형인 이유 — 행을 밀었을 때 색 덩어리가 화면을 반 가르지 않고 아이콘만 또렷하게 선다.

## States

배경은 배지에만 있다 — 아래 Background 는 배지 채움을 가리킨다.

| State | Background | Brightness | Shadow | Transform | Ring | Cursor |
|---|---|---|---|---|---|---|
| `enabled` | kind 색 | 100% | none | `translateX(0)` | none | `pointer` |
| `hovered` | kind 색 | 92% | none | `translateX(0)` | none | `pointer` |
| `focused (visible)` | kind 색 | 100% | none | `translateX(0)` | `2px var(--color-border-focus)` (inset) | `pointer` |
| `pressed (active)` | kind 색 | 88% | none | `translateX(0)` | none | `pointer` |
| `disabled` | kind 색 | 100% (opacity .4) | none | `translateX(0)` | none | `not-allowed` |

- focus ring 은 **inset** 이다 — 트레이 바깥으로 나가면 행 경계를 넘어 잘린다.
- `transform` 을 쓰지 않는다. 버튼이 눌릴 때 움직이면 이미 손가락으로 밀어 둔 트레이와 이중으로 움직여 어지럽다.

## Behavior

| 상황 | 동작 |
|---|---|
| 왼쪽으로 드래그 | 행이 손가락을 따라간다. 최대 이동 = **슬롯 폭 합**(1개 56 / 2개 104 / 3개 152). 그보다 더 밀어도 움직이지 않는다. |
| 손을 뗌 — 이동 < 트레이 폭의 **40%** | 닫힌다. (2액션 트레이 104 기준 41.6) |
| 손을 뗌 — 이동 ≥ 40% | 열린 상태로 스냅. |
| 열린 상태에서 되돌려 밀기 | 구현체 기본값에 맡긴다. 여는 임계(40%)와 **같은 값을 닫는 쪽에도 걸지 않는다** — 두 범위가 맞물려 아예 열리지 않는다. (웹·recipe 는 되돌려 민 거리가 트레이 폭의 **25%** 이상이면 닫는다) |
| 열린 상태에서 행 탭 | **닫기만** 한다. 상세로 들어가지 않는다 — 열어 둔 걸 못 보고 누르는 경우가 많다. |
| 액션 탭 | 트레이를 **먼저 닫고** 나서 실행한다(확인이 있으면 닫은 뒤 확인 다이얼로그). 열어 둔 채 띄우면 취소하고 돌아왔을 때 그대로 열려 있고, 실행한 경우엔 사라진 행 자리에 트레이만 남는다. |
| 다른 행을 드래그 | 먼저 열린 행이 닫힌다. **한 번에 하나만** 열린다. |
| 리스트 스크롤 | 열린 행이 닫힌다. |
| 오른쪽으로 드래그 | 아무 일도 없다. 왼쪽 방향만 쓴다(RTL 은 아래 참고). |
| 끝까지 밀기(full swipe) | **액션을 실행하지 않는다.** 트레이가 열릴 뿐이다. |

**끝까지 밀어도 실행하지 않는 이유** — iOS Mail 은 full swipe 로 바로 삭제하지만, 그건 되돌리기(Undo)가 있기 때문이다. 여기엔 없다. 밀다가 손이 미끄러져 지워지는 것보다 한 번 더 누르는 게 낫다.

**파괴적 액션은 확인을 받는다** — `destructive` kind 는 누른 즉시 실행하지 않고 **구현체의 확인 다이얼로그**로 확인한다(웹 `ConfirmDialog` · 앱 `PConfirmDialog` — 둘 다 [`alert-dialog`](alert-dialog.md) 시각을 따른다). 같은 항목의 삭제가 상세 화면에서든 스와이프에서든 같은 모양으로 떠야 하므로, 이 컴포넌트만 다른 다이얼로그를 쓰지 않는다. 스와이프가 삭제까지의 거리를 줄이는 만큼, 줄어든 만큼을 확인 단계로 되돌려 놓는다.

**애니메이션** — 열기/닫기 `motion-duration-fast` + `motion-ease-out`. 드래그 중에는 손가락을 1:1 로 따라가며 애니메이션을 쓰지 않는다(따라오는 속도가 어긋나면 붙어 있다는 느낌이 깨진다).

### 제스처 판정

리스트에서 주 동작은 **세로 스크롤**이다. 가로 제스처는 세로를 방해하지 않는 선에서만 가져간다.

| 항목 | 값 | 이유 |
|---|---|---|
| 데드존 | 8px | 이보다 짧은 이동은 탭으로 본다. 축을 판정하지 않는다. |
| 축 확정 | `abs(dx) > abs(dy) × 1.5` (≈33.7° 이내) | 45°(1배)로 잡으면 세로로 훑는 중 손가락이 조금만 기울어도 스크롤이 끊긴다. 세로에 여유를 준다. |
| 세로 스크롤 | `touch-action: pan-y` 로 **브라우저에 남긴다** | `preventDefault` 로 직접 처리하지 않는다 — 관성·바운스가 OS 것과 달라진다. |
| 드래그 중 | 텍스트 선택·롱프레스 콜아웃 억제 | 가로로 미는 동안 선택 핸들이나 컨텍스트 메뉴가 뜨면 제스처가 죽는다. |

세로로 확정된 제스처는 손을 뗄 때까지 가로로 되돌리지 않는다 — 판정이 도중에 바뀌면 행이 스크롤 중에 흔들린다.

## Platform

**모바일 전용이다.** 데스크톱(포인터 장치)에서는 트레이를 쓰지 않는다 — 마우스로 행을 미는 건 익숙한 동작이 아니고, 넓은 화면에서는 hover 로 액션을 드러내는 편이 낫다. 감싸는 컨테이너는 뷰포트가 데스크톱이면 **행을 그대로 통과시킨다**(래핑 자체를 걷어낸다).

| | 모바일 | 데스크톱 |
|---|---|---|
| 트레이 | 스와이프로 노출 | 없음 — 행만 렌더 |
| 액션 접근 | 스와이프 → 버튼 | 행 탭 → 상세 → 수정·삭제 |

**판정은 뷰포트 폭이다**(Desk 는 768 미만이 모바일). 포인터 타입(`pointer: coarse`)으로 가르지 않는다 — 터치 노트북이 데스크톱 레이아웃에서 스와이프를 갖게 된다. 태블릿 밴드는 데스크톱 셸이므로 트레이가 없고, 대체 경로는 행 탭 → 상세다.

## Accessibility

| 기준 | 판정 |
|---|---|
| **WCAG 2.5.5** Target Size (Enhanced, AAA) — 44×44 | ✅ 슬롯 48~56 × 행 높이(min 56). 배지(36)가 아니라 슬롯 전체가 눌린다. |
| **WCAG 2.5.8** Target Size (Minimum, AA) — 24×24 | ✅ |
| **WCAG 2.1.1** Keyboard | ⚠️ 스와이프는 포인터 전용 제스처다. **대체 경로가 반드시 있어야 한다** — 행 탭 → 상세 → 수정·삭제가 그 경로이며, 스와이프는 어디까지나 지름길이다. 스와이프로만 닿는 액션을 만들지 않는다. |
| **WCAG 2.5.1** Pointer Gestures | ✅ 한 손가락 드래그(다중 포인터·경로 기반 제스처 아님) + 위 대체 경로. |
| **WCAG 1.4.11** Non-text Contrast | ✅ 배지 채움 대 행 배경 3:1+. `neutral` 은 대비가 낮아 **라벨 텍스트로 식별**한다. |
| **WCAG 1.4.3** Color Contrast (text ≥ 4.5:1) | 배지 안 아이콘은 `--color-text-on-accent` × 각 채움(button.md 와 같은 조합). 라벨은 배지 밖이라 행 배경 대비로 본다 — `destructive` 라벨은 다크에서 `--color-error-light` 로 갈린다(base `--color-error` 는 `surface-default-dark` 대비 3.0:1 로 미달, light 변형은 5.24:1). |
| **ARIA** | 트레이는 행 뒤에 항상 존재하므로 접힌 상태에서 `aria-hidden="true"`. 열리면 해제한다 — 안 그러면 스크린리더가 모든 행마다 "수정 삭제" 를 읽는다. |
| **접근명** | 액션의 접근명은 `라벨 + 행 제목`(예: "삭제: 스타벅스"). 라벨만 두면 열린 트레이를 훑을 때 어느 행의 삭제인지 알 수 없다. |
| **Escape** | 열린 트레이는 `Escape` 로 닫고 포커스를 행으로 되돌린다. |
| **Reduced motion** | `prefers-reduced-motion: reduce` 면 열기/닫기 애니메이션을 끄고 즉시 전환. 드래그 추종은 애니메이션이 아니므로 그대로 둔다. |

## RTL

행이 미는 방향이 뒤집힌다 — RTL 에서는 **오른쪽으로** 밀고 트레이가 **왼쪽**에서 나온다. `translateX` 부호와 트레이 정렬을 `:dir(rtl)` 로 분기한다. 액션 순서는 그대로다(가장 파괴적인 것이 손가락이 끝까지 간 쪽).

> `DESIGN.desk.md` 의 "메모 카드 swipe-to-delete → RTL 시 우측 swipe 로 분기" 가 이 규칙의 첫 언급이다. 이 스펙이 그걸 컴포넌트 수준으로 확정한다.

## Do / Don't

| ✅ Do | ❌ Don't |
|---|---|
| 액션 1~3개 | 4개 이상 — 트레이가 행 폭을 먹어 무엇을 미는지 안 보인다 |
| `destructive` 는 가장 안쪽 하나만 | 파괴적 액션 여럿 — 어느 쪽이 지우는지 헷갈린다 |
| 행 탭 = 상세(원래 동작) 유지 | 스와이프를 유일한 경로로 만들기 — 키보드·스크린리더가 닿지 못한다 |
| 삭제는 확인 다이얼로그 | 누르는 즉시 삭제 — 되돌릴 수단이 없다 |

## Migration notes

- 신규 컴포넌트(v1). 기존 리스트를 바꾸지 않고 **감싸기만** 하므로 되돌리기가 쉽다 — 래퍼를 걷어내면 원래 리스트다.
- **v1 초안은 72px 사각 트레이였다**(`swipe-actions.history/v1-rect-tray.md`). 실기기에서 보니 색
  덩어리가 화면을 반 갈라 행보다 트레이가 먼저 눈에 들어왔다. 원형 배지로 바꾸고 트레이 배경을
  걷어내 색이 아이콘에만 남게 했다 — 앱 구현이 먼저 그 모습으로 갔고 이 스펙이 뒤따라 정합한다.
- 1차 적용 대상: 가계부 · 문자함 · 할일 · 메모. 문자함은 편집이 없어 `destructive` 하나만 쓴다 — **액션이 조립형이어야 하는 이유가 여기서 나온다.**
- 메모는 2열 카드 그리드라 이 패턴이 성립하지 않는다. 세로 리스트로 바꾼 뒤 적용한다.
  **로딩 스켈레톤도 같이 바꾼다** — 본문만 리스트로 바꾸면 로딩 중엔 카드 그리드였다가 데이터가 오는 순간
  화면이 통째로 튄다.
- **"관리형 화면은 기존 UI 유지" 를 걷어냈다(2026-08).** 패턴이 처음 나올 때 범위를 좁혀 두려고
  넣은 Do/Don't 줄이었다. 붙여 보니 화면이 관리형이냐 아니냐는 기준이 아니었다 — 같은 일을 두
  방법으로 하게 되는 건 **행에 편집 버튼이 이미 보일 때**고, 모바일 관리 리스트는 행에 셰브론만
  있지 그 버튼이 없다(인라인 아이콘은 데스크톱 분기 전용이고 데스크톱은 애초에 트레이를 안 쓴다).
  줄을 남겨 두면 이미 적용된 화면들이 전부 위반으로 읽힌다. 중복을 막는 실제 장치는 위에 그대로
  있다 — `행 탭 = 상세(원래 동작) 유지`.
- 적용 대상은 고정 목록이 아니다. 세로 리스트이고 행마다 할 수 있는 일이 있으면 붙는다.
  위 "1차 적용 대상" 은 처음 나간 순서를 적어 둔 것이지 허용 목록이 아니다.
