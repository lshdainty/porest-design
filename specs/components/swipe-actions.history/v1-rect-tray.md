# Swipe Actions

> 리스트 행을 왼쪽으로 밀면 오른쪽에서 액션 버튼이 드러나는 모바일 전용 패턴. iOS Mail·메시지의 스와이프와 같은 동작으로, 행을 열어 상세로 들어가지 않고도 편집·삭제 같은 자주 쓰는 액션에 바로 닿게 한다.

리스트 행 자체를 다시 만들지 않는다 — **기존 행을 감싸는 컨테이너**다. 행의 시각·탭 동작은 그대로 두고 뒤에 액션 트레이를 붙인다. 그래서 `expense-row` 든 `todo-row` 든 감싸기만 하면 같은 제스처를 얻는다.

**액션은 고정 목록이 아니다.** 항목마다 할 수 있는 일이 달라서(문자함은 편집이 없고, 메모는 고정이 있다) 호출처가 1~3개를 조립한다. 스펙은 액션의 **모양과 배치**를 정의하고 **무엇을 넣을지는 정의하지 않는다**.

## Anatomy

```
     ← 왼쪽으로 드래그
┌──────────────────────────────────┬────────┬────────┐
│ ⓐ row (기존 리스트 행 그대로)      │  ⓒ     │  ⓒ     │
│    탭 = 원래 동작(상세 열기)        │ 편집   │ 삭제   │
│                                  │        │        │
└──────────────────────────────────┴────────┴────────┘
 └─ ⓑ track (행이 밀리는 만큼 트레이가 드러난다) ─────┘
```

| ⓐ row | 감싸는 대상. 스펙은 행의 내부를 정의하지 않는다 — 높이·패딩·배경 전부 원래 행 것을 쓴다. 드래그 중 `transform: translateX(-N)` 만 받는다. |
| ⓑ track | 행 뒤에 깔리는 액션 트레이. 행과 같은 높이. `background: var(--color-surface-default)` — 트레이 자체는 색이 없고 각 액션이 자기 색을 칠한다. |
| ⓒ action | 세로 꽉 찬 버튼. 아래 Sizes·Kinds 표. 오른쪽 끝이 가장 파괴적인 액션(관례: 삭제). |

## Kinds

액션 하나의 색·의미. `destructive` 는 **트레이의 마지막(가장 오른쪽)** 에만 둔다 — 손가락이 끝까지 밀었을 때 닿는 자리라 실수로 눌리기 가장 쉽고, 그래서 위치를 예측 가능하게 고정한다.

| Kind | Background | Foreground | 의미 | 사용처 |
|---|---|---|---|---|
| `neutral` | `--color-bg-page` | `--color-text-primary` | 부수 동작 | 고정, 보관, 공유 |
| `primary` | `--color-primary` | `--color-text-on-accent` | 주 동작 | 편집 |
| `destructive` | `--color-error` | `--color-text-on-accent` | 되돌리기 어려움 | 삭제 |

## Sizes

액션 버튼은 단일 사이즈다. 행 높이를 따라가므로 Height 는 컨테이너가 정한다.

| Size | Width | Height | Padding (Y · X) | Font (token) | Font (px) | Icon | Radius | Touch (AA · AAA) |
|---|---|---|---|---|---|---|---|---|
| `default` | 72 | 행 높이 (min 56) | `spacing-sm` (8) · `spacing-sm` (8) | `text-caption` | 12 / 600 / 1.3 | 20 | `0` (토큰 없음 — 아래 참고) | ✅ · ✅ |

- Width 72 는 두 손가락 폭이 아니라 **한글 두 글자("편집"/"삭제") + 20px 아이콘이 겹치지 않는 최소치**. 이보다 좁히면 글자가 줄바꿈된다.
- Height 는 행을 따라가되 **56 미만이면 56 으로 올린다** — WCAG 2.5.5(AAA, 44×44)를 액션 높이가 밑돌지 않게. 행이 그보다 낮으면 트레이만 넘치게 두지 말고 행 높이 자체를 재검토한다.
- Radius 는 **0** 이다. 트레이는 행에 붙어 잘려 나오는 면이라 모서리를 굴리면 행과 어긋나 보인다.
  `radius-none` 토큰은 없다 — 굴리지 않는 곳은 토큰을 쓰지 않는 게 기존 관례라 값으로 둔다.

## States

| State | Background | Brightness | Shadow | Transform | Ring | Cursor |
|---|---|---|---|---|---|---|
| `enabled` | kind 색 | 100% | none | `translateX(0)` | none | `pointer` |
| `hovered` | kind 색 | 92% | none | `translateX(0)` | none | `pointer` |
| `focused (visible)` | kind 색 | 100% | none | `translateX(0)` | `2px var(--color-border-focus)` (inset) | `pointer` |
| `pressed (active)` | kind 색 | 88% | none | `translateX(0)` | none | `pointer` |
| `disabled` | kind 색 | 100% (opacity .4) | none | `translateX(0)` | none | `not-allowed` |

- focus ring 은 **inset** 이다 — 트레이 바깥으로 나가면 행 경계를 넘어 잘린다.
- `transform` 을 쓰지 않는다. 버튼이 눌릴 때 움직이면 이미 손가락으로 밀어 둔 트레이와 이중으로 움직여 어지럽다.

## Behavior

| 상황 | 동작 |
|---|---|
| 왼쪽으로 드래그 | 행이 손가락을 따라간다. 최대 이동 = 액션 개수 × 72. 그보다 더 밀면 저항(rubber band). |
| 손을 뗌 — 이동 < 트레이 폭의 **40%** | 닫힌다. |
| 손을 뗌 — 이동 ≥ 40% | 열린 상태로 스냅. |
| 열린 상태에서 행 탭 | **닫기만** 한다. 상세로 들어가지 않는다 — 열어 둔 걸 못 보고 누르는 경우가 많다. |
| 다른 행을 드래그 | 먼저 열린 행이 닫힌다. **한 번에 하나만** 열린다. |
| 리스트 스크롤 | 열린 행이 닫힌다. |
| 오른쪽으로 드래그 | 아무 일도 없다. 왼쪽 방향만 쓴다(RTL 은 아래 참고). |
| 끝까지 밀기(full swipe) | **액션을 실행하지 않는다.** 트레이가 열릴 뿐이다. |

**끝까지 밀어도 실행하지 않는 이유** — iOS Mail 은 full swipe 로 바로 삭제하지만, 그건 되돌리기(Undo)가 있기 때문이다. 여기엔 없다. 밀다가 손이 미끄러져 지워지는 것보다 한 번 더 누르는 게 낫다.

**파괴적 액션은 확인을 받는다** — `destructive` kind 는 누른 즉시 실행하지 않고 [`alert-dialog`](alert-dialog.md) 로 확인한다. 스와이프가 삭제까지의 거리를 줄이는 만큼, 줄어든 만큼을 확인 단계로 되돌려 놓는다.

**애니메이션** — 열기/닫기 `motion-duration-fast` + `motion-ease-out`. 드래그 중에는 손가락을 1:1 로 따라가며 애니메이션을 쓰지 않는다(따라오는 속도가 어긋나면 붙어 있다는 느낌이 깨진다).

## Platform

**모바일 전용이다.** 데스크톱(포인터 장치)에서는 트레이를 쓰지 않는다 — 마우스로 행을 미는 건 익숙한 동작이 아니고, 넓은 화면에서는 hover 로 액션을 드러내는 편이 낫다. 감싸는 컨테이너는 뷰포트가 데스크톱이면 **행을 그대로 통과시킨다**(래핑 자체를 걷어낸다).

| | 모바일 | 데스크톱 |
|---|---|---|
| 트레이 | 스와이프로 노출 | 없음 — 행만 렌더 |
| 액션 접근 | 스와이프 → 버튼 | 행 탭 → 상세 → 편집·삭제 |

## Accessibility

| 기준 | 판정 |
|---|---|
| **WCAG 2.5.5** Target Size (Enhanced, AAA) — 44×44 | ✅ 72 × 56 |
| **WCAG 2.5.8** Target Size (Minimum, AA) — 24×24 | ✅ |
| **WCAG 2.1.1** Keyboard | ⚠️ 스와이프는 포인터 전용 제스처다. **대체 경로가 반드시 있어야 한다** — 행 탭 → 상세 → 편집·삭제가 그 경로이며, 스와이프는 어디까지나 지름길이다. 스와이프로만 닿는 액션을 만들지 않는다. |
| **WCAG 2.5.1** Pointer Gestures | ✅ 한 손가락 드래그(다중 포인터·경로 기반 제스처 아님) + 위 대체 경로. |
| **WCAG 1.4.11** Non-text Contrast | ✅ `primary`/`destructive` 배경 대 트레이 3:1+. `neutral` 은 배경 대비가 낮아 **텍스트 대비(4.5:1)로 식별**한다. |
| **WCAG 1.4.3** Color Contrast (text ≥ 4.5:1) | `primary`/`destructive` 는 `--color-text-on-accent` × 각 배경 = 4.5:1+ (button.md 와 같은 조합, `npm run lint:dark` 로 검증됨). `neutral` 은 `--color-text-primary` × `--color-bg-page`. |
| **ARIA** | 트레이는 행 뒤에 항상 존재하므로 접힌 상태에서 `aria-hidden="true"`. 열리면 해제한다 — 안 그러면 스크린리더가 모든 행마다 "편집 삭제" 를 읽는다. |
| **Reduced motion** | `prefers-reduced-motion: reduce` 면 열기/닫기 애니메이션을 끄고 즉시 전환. 드래그 추종은 애니메이션이 아니므로 그대로 둔다. |

## RTL

행이 미는 방향이 뒤집힌다 — RTL 에서는 **오른쪽으로** 밀고 트레이가 **왼쪽**에서 나온다. `translateX` 부호와 트레이 정렬을 `:dir(rtl)` 로 분기한다. 액션 순서는 그대로다(가장 파괴적인 것이 손가락이 끝까지 간 쪽).

> `DESIGN.desk.md` 의 "메모 카드 swipe-to-delete → RTL 시 우측 swipe 로 분기" 가 이 규칙의 첫 언급이다. 이 스펙이 그걸 컴포넌트 수준으로 확정한다.

## Do / Don't

| ✅ Do | ❌ Don't |
|---|---|
| 액션 1~3개 | 4개 이상 — 트레이가 행 폭을 먹어 무엇을 미는지 안 보인다 |
| `destructive` 는 맨 오른쪽 하나만 | 파괴적 액션 여럿 — 어느 쪽이 지우는지 헷갈린다 |
| 행 탭 = 상세(원래 동작) 유지 | 스와이프를 유일한 경로로 만들기 — 키보드·스크린리더가 닿지 못한다 |
| 삭제는 확인 다이얼로그 | 누르는 즉시 삭제 — 되돌릴 수단이 없다 |
| 관리형 화면은 기존 UI 유지 | 설정·카테고리·프리셋처럼 이미 편집 버튼이 있는 화면에 덧붙이기 — 같은 일을 두 방법으로 하게 된다 |

## Migration notes

- 신규 컴포넌트(v1). 기존 리스트를 바꾸지 않고 **감싸기만** 하므로 되돌리기가 쉽다 — 래퍼를 걷어내면 원래 리스트다.
- 1차 적용 대상: 가계부 · 문자함 · 할일 · 메모. 문자함은 편집이 없어 `destructive` 하나만 쓴다 — **액션이 조립형이어야 하는 이유가 여기서 나온다.**
- 메모는 2열 카드 그리드라 이 패턴이 성립하지 않는다. 세로 리스트로 바꾼 뒤 적용한다.
